Writing a rail is two functions

Every rail above is the same template. The kernel decides; a rail only turns that decision into one rail-specific necessary input — a check run, a deploy gate, an apply gate. You fill in two hooks. The order, the token check, and fail-closed live in the base class, where a rail can't skip them.

recheck_against_context

# no side effects — runs BEFORE any capability
def recheck_against_context(self, token, req):
    recomputed = chain.chain_hash(req.intent,
                              req.cart, req.payment)
    bound = (recomputed == token.chain_hash
             and self._well_formed(req)
             and self._context_matches_cart(req))
    if not bound:
        return (False, "effect/context mismatch "
                       "vs the approved Cart")
    return True, "bound to this transaction"

produce_capability

# reached ONLY when token + recheck both pass
def produce_capability(self, token, req):
    head_sha = _parse_head_sha(req.context.recipient)
    check = self._rail.open_check(
        token.chain_hash, head_sha)
    ref = self._rail.conclude(
        check, token.chain_hash, "success")
    # the protected-branch merge gate is satisfied
    return AuthorizationResult(
        True, "gate satisfied", payment_ref=ref)

Switching rails above changed only these two functions and the gate at the bottom. The eleven checks never moved — they're the kernel, and the kernel stays rail-agnostic. That's why an attack lands on the same check whether it's a merge, a deploy, or an infra apply.

Not a mockup

The gauntlet and resolution verdicts here are regenerated from the unmodified kernel on every build (python -m demos.build_demo) — the reason strings are the verifier's own output, not narration. The AgentDojo figures are a recorded run on a live model (gpt-4o-mini), reproducible with the eval harness — the one thing on this page not regenerated by the build. Swap a live GitHub App, a real promotion controller, or a Terraform runner in for the mock rail and the same gauntlet trace plays against your workflow.
